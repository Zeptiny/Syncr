# ADR 0008: The web UI

- Status: accepted (unreleased until v2.0.0)
- Date: 2026-11-07

## Context

Milestone 3 gives Syncr its first user interface. People use it to sign in,
add storage (remotes), enroll workers, run transfers and follow them live.
The controller already speaks Connect (JSON over HTTP) for every operation,
so the UI can be a pure API client. Three constraints shape it:

- **One binary.** The controller ships as a single Go binary and Docker
  image; the UI must be served by it, from the same origin as the API.
- **No Node for Go work.** `go build ./...`, `go test ./...` and the Go
  linters must keep working on machines without Node, and build output must
  stay out of git.
- **Forms come from the server.** Backends are described by the registry
  (ADR 0007, `BackendService.ListBackends`); adding one must not need a
  frontend change.

## Decision

### Stack

A React 19 single-page app in `web/`, built by Vite 8 into `web/dist`:

- TanStack Router with file routes (`src/routes`); `routeTree.gen.ts` is
  generated by `tsr generate` and committed, and CI fails on drift.
- TanStack Query through `@connectrpc/connect-query`; the TypeScript
  clients are generated by `protoc-gen-es` into `web/src/gen` (`buf
  generate`).
- Tailwind CSS 4 with light and dark theme tokens in `src/index.css`;
  shadcn/ui sources copied into `src/components/ui` (we own and may edit
  them); Radix primitives underneath.
- react-hook-form with zod, uPlot for the live chart, sonner for toasts.
- IBM Plex Sans and Plex Mono, self-hosted from npm (`@fontsource`), so the
  page loads nothing from third parties.

Every dependency is pinned exactly in `package.json` and locked in
`package-lock.json`. `overrides` pins `@tanstack/query-core` and
`@connectrpc/connect-query-core` so react-query and connect-query share one
QueryClient implementation.

### Structure

- `src/components/app` is the app's component library: AppShell,
  PageHeader, Panel, EmptyState, ErrorState, DataTable (loading, empty and
  error states, keyset pager), StatusBadge, StatCard/StatGrid,
  KeyValueList, FilterBar, RelativeTime, ConfirmDialog, CopyCommand,
  DescriptorForm, ProgressChart and the pickers (RemotePicker,
  WorkerPicker, PathInput, LocationEditor). Pages are composed from these
  only, so every list, form and empty state looks and behaves the same.
- `src/features/<area>` holds the pages; `src/routes` only binds them to
  URLs, search params and guards.
- `src/lib` holds the transport, the query client, error mapping and
  formatting; `src/hooks` the session, backends and live-job hooks.

### Forms from descriptors

`DescriptorForm` turns a `Backend` descriptor into a form: a zod schema
(required fields, integer and enum parsing, at least two union members), a
field component per kind (text, secret, int, bool, enum, members) and an
"Advanced options" section for advanced fields. Secrets are write-only:
when editing, an empty secret keeps the stored value, a typed one replaces
it, and optional secrets can be cleared (`clear_secrets`). Server
`ValidationError` details (`options.x`, `secrets.x`, `members[i].path`) are
mapped back onto their fields.

### Auth and CSRF in the browser

The session is an HttpOnly cookie set by the controller (ADR 0006); the SPA
never sees it. Every call goes through one Connect transport whose
interceptor adds `X-Syncr-CSRF: 1`, which another origin cannot send without
a CORS preflight the controller never allows. The signed-in layout's guard
calls `GetSession`; without a session it asks `GetSetupStatus` and sends the
user to the setup wizard or to `/login?redirect=…` (same-origin paths only).
Any later UNAUTHENTICATED answer drops the cached session and returns to the
login page. Roles only hide controls; the server enforces them.

### Live jobs

The job page reads `GetJob`, loads the stored samples (`ListJobSamples`)
and follows `WatchJob`. On DEADLINE_EXCEEDED, UNAVAILABLE or a dropped
connection it reconnects with backoff from 1 s doubling to 30 s, and stops
once the job is terminal. Job messages update the query cache, so every
view of the job stays current. Throughput is Δbytes/Δt between samples,
never negative.

### Serving and embedding

- `web/embed.go` (package `web`, standard library only) exposes `FS()`.
  With `-tags webui` it embeds `all:dist`; without the tag it embeds
  `web/placeholder`, a page that says the binary was built without the UI.
  So plain `go build` needs no Node, and `dist` stays gitignored. Release,
  Docker and CI builds run `npm ci && npm run build` in `web/` and then
  build with `-tags webui`.
- `api.Deps.UI` takes that file system; `internal/adapters/api/spa.go`
  serves it for every path the API does not claim:
  - existing files directly; `/assets/*` (content-hashed by Vite) with
    `Cache-Control: public, max-age=31536000, immutable`;
  - a missing `/assets/*` file is a 404, never the app shell, so a stale
    page fails loudly instead of parsing HTML as script;
  - any other GET or HEAD gets `index.html` with `Cache-Control: no-cache`
    (client routes); other methods get 405;
  - `/syncr.v1.*` and `/healthz` are never answered with the UI, so an
    unmounted service still looks absent;
  - every UI response carries `Content-Security-Policy: default-src 'self';
    script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self'
    data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none';
    form-action 'self'`, `X-Content-Type-Options: nosniff` and
    `Referrer-Policy: same-origin`.
- The CSP forbids inline scripts, so the theme is applied before first
  paint by a small external `theme-init.js` rather than an inline snippet.
  `style-src 'unsafe-inline'` remains because Radix positions popovers with
  inline styles.

### Development

- `npm run dev` proxies `^/syncr\.v1\.` and `/healthz` to
  `SYNCR_DEV_API` (default `http://127.0.0.1:8080`) without changing the
  Origin, so the controller's cross-origin protection accepts the calls.
- `VITE_SYNCR_MOCK=1 npm run dev` serves fixture data from an in-memory
  Connect router instead (`src/mock`, reusing `src/test/fixtures.ts`). It is
  imported only behind `import.meta.env.DEV`, so production bundles do not
  contain it.
- `npm run screenshots` (`scripts/screenshots.mjs`) drives the cached
  Chromium with playwright-core 1.47.2 to take the PR screenshots; it is
  never run in CI.
- Tests run in Vitest with jsdom and Testing Library, against
  `createRouterTransport` mocks (`src/test/render.tsx`).

## Consequences

- The controller binary carries the UI only when built with `-tags webui`;
  a plain `go build` binary serves the placeholder page at `/` and the full
  API.
- Adding a backend descriptor in Go is enough for it to appear in the UI.
- Every new page should be assembled from `src/components/app`; adding a
  one-off table or empty state is a review smell.
- The CI `web` job (Node 26) checks route-tree drift, types, lint,
  formatting, tests and the build, and hands `web/dist` to the Go build.
