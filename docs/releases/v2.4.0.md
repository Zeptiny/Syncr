# Syncr 2.4.0

Syncr 2.4 adds **metrics for Prometheus** at `/metrics`, and a **fuller
dashboard**.

- **`/metrics`.** Workers up and last seen, jobs queued and running, every
  finished job by kind, worker, outcome and error code, data transferred,
  run times and queue waits, each schedule's last run and last success,
  and the restic repositories' snapshots. A scrape signs in with a personal
  API token and sees what its user sees on the dashboard. Counters come
  from the database, so they survive controller restarts. Scrape
  configuration, every metric and example alerts: [metrics](../metrics.md).
- **Dashboard.** Average run time and queue wait, with a chart of each over
  the period; the jobs by kind and by worker, each with its outcomes,
  success rate, data and times; why jobs failed, by error code; how every
  schedule's latest run went and when it last succeeded; and what backups
  added to each restic repository, per day. Each row links to its jobs.

## Upgrade

- **Controller:** back up the database, then pull the new image or replace
  the binary ([running the controller](../deployment.md#upgrading)). One
  database migration (00013) runs at start: it adds the index the metrics
  count with (`jobs_totals_idx`) and drops `jobs_owner_finished_idx`, which
  the new one replaces. Building the index reads the jobs table once. No new
  setting.
- **Downgrading** to 2.3 means restoring the database backup made before
  the upgrade, as for every release ([upgrading](../upgrade.md)); the down
  script of 00013 only swaps the indexes back.
- **Workers:** nothing changes; 2.3 workers keep working.
- **Reverse proxies:** to scrape through one, let `/metrics` through like
  the API.
